Overall System Architecture (Web + SC Courier Mobile App)

End-to-end multi-tier architecture linking the React Web Portal, SC Courier Rider Mobile App, Node.js/Express Backend, Supabase Cloud (PostgreSQL + Realtime), and External Geolocation/Email Services.

      W_STAFF["Staff Dashboard\n• Approve / Accept Requests\n• Assign Riders & Dispatch Trips\n• Generate Invoices"]
      W_ADMIN["Admin Dashboard\n• Manage Staff, Riders & Branches\n• Analytics & Excel/PDF Reports\n• Full Dispatch Control"]

Sequence 1 - Customer Login and Registration

Authentication flow: registration, login, role detection and redirect to correct dashboard.

sequenceDiagram
    actor C as Customer
    participant FE as Frontend React
    participant BE as Backend Express
    participant DB as Database PostgreSQL

    C->>FE: Fill registration form
    FE->>BE: POST /api/auth/register
    BE->>DB: SELECT FROM Customer WHERE cust_email
    DB-->>BE: Empty result new user
    BE->>DB: INSERT INTO Customer
    DB-->>BE: New customer row
    BE-->>FE: 200 OK customer data
    FE-->>C: Registration successful

    C->>FE: Enter email and password
    FE->>BE: POST /api/auth/login
    BE->>DB: Check Staff table
    DB-->>BE: Not found
    BE->>DB: Check Customer table
    DB-->>BE: Match found
    BE-->>FE: role is customer name returned
    FE-->>C: Redirect to Customer Dashboard

Sequence 2 - Courier Request Booking and Dispatch

Customer books parcel, staff approves, rider is assigned, delivery tracked end-to-end.

sequenceDiagram
    actor C as Customer
    actor S as Staff
    actor R as Rider
    participant FE as Frontend
    participant BE as Backend
    participant DB as Database

    C->>FE: Fill Courier Request form
    FE->>BE: POST /api/courier-requests
    BE->>DB: INSERT INTO courier_req
    DB-->>BE: book_id returned
    BE-->>FE: 201 Created
    FE-->>C: Request submitted

    S->>FE: View pending courier requests
    FE->>BE: GET /api/courier-requests status Pending
    BE->>DB: SELECT FROM courier_req WHERE status is Pending
    DB-->>BE: List of requests
    BE-->>FE: Request list
    FE-->>S: Rendered table

    S->>FE: Approve request and assign rider
    FE->>BE: PATCH /api/courier-requests id
    BE->>DB: UPDATE courier_req status to Approved
    DB-->>BE: Updated row

    S->>FE: Create trip and assign rider
    FE->>BE: POST /api/trips with rider_nic and branch_id
    BE->>DB: INSERT INTO trip
    DB-->>BE: trip_id returned
    BE->>DB: INSERT INTO delivery with trip_id and book_id
    DB-->>BE: del_id returned
    BE-->>FE: 201 Created
    FE-->>S: Trip and delivery created

    R->>FE: View assigned trips
    FE->>BE: GET /api/riders/nic/deliveries
    BE->>DB: SELECT FROM delivery JOIN trip WHERE rider_nic
    DB-->>BE: Delivery list
    FE-->>R: Trip and package info

    R->>FE: Update status to Delivered
    FE->>BE: PATCH /api/deliveries id status Delivered
    BE->>DB: UPDATE delivery SET delivery_status to Delivered
    BE->>DB: INSERT INTO notification for customer
    DB-->>BE: Saved
    BE-->>FE: 200 OK
    FE-->>C: Parcel Delivered notification sent

Sequence 3 - ATR Activity Travel Request Workflow

Corporate customer submits ATR, client approver signs off, staff processes, rider dispatched.

sequenceDiagram
    actor C as Corporate Customer
    actor CA as Client Approver
    actor S as Staff
    actor R as Rider
    participant FE as Frontend
    participant BE as Backend
    participant DB as Database

    C->>FE: Fill ATR form with department and travel details
    FE->>BE: POST /api/atr
    BE->>DB: INSERT INTO atr with status Pending
    DB-->>BE: atr_id returned
    BE-->>FE: 201 Created
    FE-->>C: ATR submitted

    BE-->>CA: Email with approval link token
    CA->>BE: GET /api/atr/approve/token
    BE->>DB: UPDATE atr SET status to ClientApproved
    DB-->>BE: Updated
    BE-->>CA: Approval confirmed

    S->>FE: View ClientApproved ATRs
    FE->>BE: GET /api/atr status ClientApproved
    BE->>DB: SELECT FROM atr WHERE status is ClientApproved
    DB-->>BE: ATR list
    FE-->>S: ATR table displayed

    S->>FE: Approve ATR and assign rider
    FE->>BE: PATCH /api/atr id status StaffApproved rider_nic
    BE->>DB: UPDATE atr SET status StaffApproved and assigned_rider_nic
    DB-->>BE: OK
    FE-->>S: ATR dispatched to rider

    R->>FE: View assigned ATR trip
    FE->>BE: GET /api/riders/nic/atr
    BE->>DB: SELECT FROM atr WHERE assigned_rider_nic
    DB-->>BE: ATR details
    FE-->>R: ATR info displayed

    R->>FE: Submit actual cost and distance
    FE->>BE: PATCH /api/atr id with actual_distance and actual_cost
    BE->>DB: UPDATE atr SET actual values and status Completed
    BE->>DB: INSERT INTO invoice with total_amount
    BE->>DB: INSERT INTO atr_invoice linking record
    DB-->>BE: Invoice created
    FE-->>C: Invoice generated and sent

Sequence 4 - Personal Door to Door Delivery

Customer requests personal delivery, staff schedules and assigns rider, rider delivers.

sequenceDiagram
    actor C as Customer
    actor S as Staff
    actor R as Rider
    participant FE as Frontend
    participant BE as Backend
    participant DB as Database

    C->>FE: Fill Personal Delivery form with pickup and drop address
    FE->>BE: POST /api/personal-deliveries
    BE->>DB: INSERT INTO personal_delivery with status Pending
    DB-->>BE: pd_id returned
    BE-->>FE: 201 Created
    FE-->>C: Request submitted

    S->>FE: View pending personal deliveries
    FE->>BE: GET /api/personal-deliveries status Pending
    BE->>DB: SELECT FROM personal_delivery WHERE status is Pending
    DB-->>BE: Delivery list
    FE-->>S: Table of pending deliveries

    S->>FE: Schedule delivery and assign rider
    FE->>BE: PATCH /api/personal-deliveries id with scheduled_date and rider_nic
    BE->>DB: UPDATE personal_delivery status to Scheduled and set assigned_rider_nic
    DB-->>BE: Updated
    FE-->>S: Delivery scheduled

    R->>FE: View scheduled deliveries
    FE->>BE: GET /api/riders/nic/personal-deliveries
    BE->>DB: SELECT FROM personal_delivery WHERE assigned_rider_nic
    DB-->>BE: Delivery details
    FE-->>R: Delivery shown on map

    R->>FE: Accept and start delivery
    FE->>BE: PATCH /api/personal-deliveries id status InTransit
    BE->>DB: UPDATE personal_delivery to InTransit and set accepted_by rider_nic
    DB-->>BE: OK

    R->>FE: Mark as Delivered
    FE->>BE: PATCH /api/personal-deliveries id status Delivered
    BE->>DB: UPDATE personal_delivery status to Delivered
    DB-->>BE: OK
    BE-->>FE: 200 OK
    FE-->>C: Package delivered notification sent
